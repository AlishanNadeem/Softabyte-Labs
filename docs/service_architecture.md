# Service Architecture

**Project:** Softabyte Labs  
**Phase:** 0 — Planning only  
**Date:** August 19, 2026

This document defines the six core services, why each deserves a dedicated page, and how they stay differentiated.

Related documents: `keyword_map.md`, `industry_strategy.md`, `internal_linking_strategy.md`, `website_architecture.md`

---

## 1. Core rule

Softabyte Labs has **six core services**. Ecommerce is **not** one of them.

| Core service | URL | Dedicated page? |
|---|---|---|
| Custom Software Development | `/services/custom-software-development/` | Yes |
| Web Development | `/services/web-development/` | Yes |
| Mobile App Development | `/services/mobile-app-development/` | Yes |
| AI & Automation | `/services/ai-automation/` | Yes — one page only |
| UI/UX Design | `/services/ui-ux-design/` | Yes |
| Hosting & Infrastructure | `/services/hosting-infrastructure/` | Yes — one page only |

## 2. Hub page

**URL:** `/services/`  
**Role:** Help a US buyer choose the right engagement, not rank for every service keyword.  
**Primary intent:** Commercial investigation — “what does this company actually do?”  
**H1 recommendation:** Software, product, and infrastructure services  
**CTA:** Start a project / Talk through your roadmap

The hub should briefly define each service, contrast them, and link down. It should not duplicate the full service pages.

## 4. Custom Software Development

**URL:** `/services/custom-software-development/`  
**Primary keyword:** custom software development company  
**Intent:** Commercial — hire a partner to build or replace business software  
**Audience:** Founders, CEOs, COOs, CTOs replacing spreadsheets, legacy tools, or misfit SaaS  
**User problem:** Off-the-shelf software does not match the workflow.  
**Business problem:** Operations are slow, error-prone, or stuck in tools the company does not control.  
**Value proposition:** Softabyte Labs designs and builds software around the business, then can host and improve it.

### Recommended page structure

1. H1: Custom software for US businesses that have outgrown generic tools
2. Who this is for / who this is not for
3. Problems custom software actually solves
4. What we build (internal tools, portals, platforms, productized operations)
5. Process from discovery to launch
6. How this differs from buying SaaS
7. Related services: AI, web, mobile, hosting
8. Ecommerce and other industry examples as use cases, not duplicate pages
9. FAQs
10. CTA

### Supporting topics on-page, not as child URLs

- Custom vs off-the-shelf
- Discovery and scoping
- Integration with existing systems
- Ownership of code and IP

### CTAs

- Primary: Request a discovery call
- Secondary: See how we work (`/process/`)

## 7. AI & Automation — one core page

**URL:** `/services/ai-automation/`  
**Primary keyword:** AI automation for business  
**Secondary cluster:** AI integration, workflow automation, AI-powered applications, business process automation  
**Intent:** Commercial — apply AI/automation to real operations, not a science project  
**Audience:** COOs, operations managers, founders, CTOs  
**Decision:** **One strong page. No child pages at launch.**

### Why not multiple AI pages

Search queries around AI development, AI chatbots, AI assistants, and workflow automation substantially overlap for an agency buyer. Thin pages for each term would cannibalize each other and look like a content mill.

ScienceSoft and Appinventiv can support large AI trees because they have years of case studies and headcount. Softabyte Labs should build **topical authority on one page plus supporting blog posts**.

### On-page sections (not URLs)

- Practical AI vs hype
- Workflow and business process automation
- AI integration into existing software
- AI-powered features inside web/mobile products
- Assistants and chat interfaces when they serve a workflow
- Data, privacy, and human review
- What we will not build (unsupported “autonomous company” claims)

### CTAs

- Primary: Book an automation diagnostic
- Secondary: Custom software or hosting, depending on context

## 9. Hosting & Infrastructure — one core page

**URL:** `/services/hosting-infrastructure/`  
**Primary keyword:** managed application hosting  
**Secondary cluster:** application hosting, cloud hosting for web apps, deployment, monitoring, application maintenance  
**Intent:** Commercial — someone to run, deploy, and look after the product after launch  
**Decision:** **One page. Do not split hosting, DevOps, monitoring, and maintenance at launch.**

### Why one page

For Softabyte Labs buyers, “host it,” “deploy it,” “watch it,” and “maintain it” are usually one buying decision: **who owns the running system?**

Pure commodity hosting (shared WordPress hosting, generic VPS) is not the positioning. This page is **managed hosting and infrastructure for applications Softabyte Labs builds or inherits**.

### On-page sections (not URLs)

- Managed hosting for web apps and custom software
- Cloud architecture at a business level (not a hyperscaler clone page)
- Deployment and environments
- Monitoring, backups, and uptime ownership
- Maintenance and improvement retainers
- Security basics without fake certifications
- Handoff if the client has an internal team

### Do not compete as

- AWS reseller landing pages
- “Cheap website hosting” pages

### CTAs

- Primary: Talk about hosting and care
- Secondary: Custom software / web development
