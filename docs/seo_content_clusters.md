# SEO Content Clusters

**Project:** Softabyte Labs
**Phase:** 11 — SEO Content System + Content Growth Architecture
**Date:** August 22, 2026

Twelve clusters: six service clusters, six industry clusters. Each cluster supports exactly one commercial pillar page. Blog content in a cluster must never adopt the pillar's primary keyword as its own H1/title — see `seo_cannibalization_audit.md`.

---

## Service clusters

### 1. Custom Software Development

- **Pillar page:** `/services/custom-software-development/`
- **Cluster purpose:** De-risk the buy-vs-build decision and build trust before a discovery call.
- **Target audience:** Founders, COOs, CTOs replacing spreadsheets, legacy tools, or misfit SaaS.
- **Search intent:** Commercial Investigation (informational lean).
- **Supporting topics:** Buy vs. build, timing signals, vendor evaluation, delivery timeline, legacy modernization.
- **Internal link direction:** Blog → Pillar (primary); Blog → Process (discovery framing); Pillar → 1-2 selected articles.
- **Cannibalization risks:** Low — see audit. Watch for a future "custom software development process" article competing with `/process/`.
- **Business priority:** High.
- **Existing content:** "Custom Software vs. Off-the-Shelf Software: How to Choose" (published, featured).

### 2. AI & Automation

- **Pillar page:** `/services/ai-automation/`
- **Cluster purpose:** Build practical, hype-free authority on automation and AI integration.
- **Target audience:** COOs, operations leaders, founders evaluating automation spend.
- **Search intent:** Commercial Investigation (informational lean).
- **Supporting topics:** Candidate identification, implementation patterns, AI integration into existing systems, when not to use AI.
- **Internal link direction:** Blog → Pillar; Blog → Custom Software (integration overlap).
- **Cannibalization risks:** Low. Existing article owns "candidate identification"; future articles must own distinct sub-topics (implementation, integration, trust/limits).
- **Business priority:** High.
- **Existing content:** "How to Identify Business Processes Worth Automating" (published).

### 3. Web Development

- **Pillar page:** `/services/web-development/`
- **Cluster purpose:** Clarify website vs. web application decisions and what premium web engineering includes.
- **Target audience:** Marketing leaders, founders, product managers.
- **Search intent:** Commercial Investigation.
- **Supporting topics:** Website vs. web app (P1), redesign signals (P1), performance/engineering standards; planned P2: SaaS startup website launch-readiness (informational, cross-supports Startups & SaaS cluster).
- **Internal link direction:** Blog → Pillar; Blog → UI/UX where design-led.
- **Cannibalization risks:** Low. Must not echo Ecommerce industry primary.
- **Business priority:** High.

### 4. Mobile App Development

- **Pillar page:** `/services/mobile-app-development/`
- **Cluster purpose:** Help buyers decide between mobile app, mobile web, and hybrid approaches.
- **Target audience:** Product leads, founders, operations leaders with field/customer app needs.
- **Search intent:** Commercial Investigation.
- **Supporting topics:** App vs. mobile website, what makes an app worth building.
- **Internal link direction:** Blog → Pillar; Blog → Web Development (channel comparison).
- **Cannibalization risks:** Low.
- **Business priority:** Medium-High.

### 5. UI/UX Design

- **Pillar page:** `/services/ui-ux-design/`
- **Cluster purpose:** Support design-led engagements, often paired with Web or Mobile builds.
- **Target audience:** Founders, product managers, marketing leaders.
- **Search intent:** Commercial Investigation.
- **Supporting topics:** Conversion-focused UX, design systems.
- **Internal link direction:** Blog → Pillar; Blog → Web/Mobile.
- **Cannibalization risks:** None identified.
- **Business priority:** Medium.

### 6. Hosting & Infrastructure

- **Pillar page:** `/services/hosting-infrastructure/`
- **Cluster purpose:** Establish trust as the team that keeps what it builds running.
- **Target audience:** Founders, CTOs, marketing ops leaders.
- **Search intent:** Commercial Investigation.
- **Supporting topics:** Managed hosting vs. DIY cloud, maintenance scope, environment discipline.
- **Internal link direction:** Blog → Pillar; Blog → Custom Software / Web (post-launch care).
- **Cannibalization risks:** Low.
- **Business priority:** Medium-High (differentiator, not primary revenue driver).

## Industry clusters

### 7. Transportation & Logistics

- **Pillar page:** `/industries/transportation-logistics/`
- **Cluster purpose:** Show operational understanding of dispatch, fleet, and visibility problems.
- **Target audience:** Carriers, freight brokers, logistics operators.
- **Search intent:** Commercial Investigation (industry).
- **Supporting topics:** Dispatch tool limits, manual work reduction, proof-of-delivery workflows.
- **Internal link direction:** Blog → Industry pillar; Blog → Custom Software / AI & Automation.
- **Cannibalization risks:** Low. Must not read as a TMS product landing page.
- **Business priority:** High.

### 8. Professional Services

- **Pillar page:** `/industries/professional-services/`
- **Cluster purpose:** Support client-delivery and operations software decisions for service firms.
- **Target audience:** Consultancies, agencies, service-based firms.
- **Search intent:** Commercial Investigation / Navigational (moderate organic expectations per `industry_strategy.md`).
- **Supporting topics:** Client onboarding automation, PSA vs. custom software, communication workflows.
- **Internal link direction:** Blog → Industry pillar; Blog → Custom Software / UI/UX.
- **Cannibalization risks:** Low. Existing client-portal article already supports this cluster (cross-industry, not vertical-exclusive).
- **Business priority:** Medium-High (site architecture value higher than raw SEO volume).
- **Existing supporting content:** "When Does a Business Need a Client Portal?" (published; supports this cluster and Custom Software / Web Development).

### 9. Ecommerce & Retail / B2B Commerce

- **Pillar page:** `/industries/ecommerce/`
- **Cluster purpose:** Go beyond generic storefront content into B2B/operational ecommerce problems.
- **Target audience:** Ecommerce operators, wholesale/distributor businesses.
- **Search intent:** Commercial Investigation (industry).
- **Supporting topics:** B2B ordering portals, storefront vs. operations software, automation without hype.
- **Internal link direction:** Blog → Industry pillar; Blog → Custom Software / AI & Automation.
- **Cannibalization risks:** Low. Must not compete with Web Development's "web development company" primary.
- **Business priority:** High.

### 10. Startups & SaaS

- **Pillar page:** `/industries/startups-saas/`
- **Cluster purpose:** Support MVP and product-architecture decisions for founders and product teams.
- **Target audience:** SaaS founders, product leaders, startup CTOs.
- **Search intent:** Commercial Investigation (industry).
- **Supporting topics:** MVP scope (P1), SaaS startup website launch-readiness before go-live (P2), SaaS architecture decisions, when to rebuild an MVP.
- **Internal link direction:** Blog → Industry pillar; Blog → Custom Software / Web / UI/UX.
- **Cannibalization risks:** Medium (preventive) — must not echo Custom Software or Web Development primaries; keep SaaS/product framing explicit.
- **Business priority:** High.

### 11. Real Estate

- **Pillar page:** `/industries/real-estate/`
- **Cluster purpose:** Support property/PropTech operations software decisions.
- **Target audience:** Brokerages, property managers, PropTech founders.
- **Search intent:** Commercial Investigation (industry).
- **Supporting topics:** Build vs. buy for property management, maintenance workflow automation, tenant/owner communication.
- **Internal link direction:** Blog → Industry pillar; Blog → Custom Software / Web.
- **Cannibalization risks:** Low.
- **Business priority:** Medium.

### 12. Healthcare

- **Pillar page:** `/industries/healthcare/`
- **Cluster purpose:** Build cautious, trust-first educational content — no compliance or clinical claims.
- **Target audience:** Healthcare org leaders, digital health founders.
- **Search intent:** Commercial Investigation (industry) — YMYL caution applies.
- **Supporting topics:** Portal planning considerations, custom vs. off-the-shelf early questions, workflow automation starting points.
- **Internal link direction:** Blog → Industry pillar; Blog → Custom Software / Mobile.
- **Cannibalization risks:** Low, but every article requires an explicit "what we do not claim" note.
- **Business priority:** Lower content-expansion priority until stronger trust/compliance assets exist (per `keyword_strategy.md`). Indexation status of the pillar page itself is a separate open item — see `seo_keyword_ownership.md` §5.
